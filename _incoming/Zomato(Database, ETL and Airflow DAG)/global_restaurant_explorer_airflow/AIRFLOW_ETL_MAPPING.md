## 2. Design Rationale & Non-Destructive Guarantees

- **No Business Logic Duplication:** The DAG never reimplements CSV parsing, validation rules, decimal quantization, SQL upserts, or Gold view definitions; every stage delegates to the tested functions inside `pipeline/etl/`.
- **Zero Large XCom Payloads:** Instead of serializing a 9,550-row Pandas DataFrame across XCom, tasks exchange lightweight JSON dictionaries (counts, hashes, paths, statuses). Re-reading/validating `zomato_cleaned.csv` takes ~0.8 seconds total and keeps every Airflow task stateless and safely retryable.
- **No Destructive Schema Operations:** `zomato_restaurant_explorer.sql` (which begins with `DROP DATABASE IF EXISTS`) is **never** executed by the DAG. Only strictly additive migrations (`001_create_etl_metadata.sql` and `002_create_gold_views.sql`) are invoked.
- **Known Existing Schema Caveat:** As documented in `REVIEW_STATUS.md`, `zomato_restaurant_explorer.sql` defines `countries.country_name VARCHAR(100) NOT NULL`, while `pipeline/etl/load_silver.py::_load_countries` inserts only `(country_code)`. Existing seeded country codes succeed cleanly via `INSERT IGNORE`, but introducing a brand-new unseeded `country_code` in MySQL strict mode will require updating `_load_countries` or pre-seeding `countries`.
